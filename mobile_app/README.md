# تطبيق رفقة بلاد الحرمين

واجهة الجوال لمشروع «رفقة بلاد الحرمين» مبنية بـ Flutter، ومتصلة بنفس قاعدة
البيانات التي يستخدمها الموقع.

## الملفات

- نقطة الدخول: `lib/main.dart`
- شاشة تسجيل الدخول: `lib/app/main.dart`
- لوحات المستخدمين: `pilgrim_dashboard.dart` ، `supervisor_dashboard.dart` ، `manager_dashboard.dart`
- **الاتصال بقاعدة البيانات: `lib/services/api_service.dart`**
- برنامج المناسك: `lib/app/journey_page.dart`
- الخريطة والمواقع: `lib/app/locations_page.dart`
- بطاقة الحاج ورقم النسك: `lib/app/identity_page.dart`
- الشعار: `assets/images/logo.png` (نفس شعار الموقع)

## الشاشات الجديدة (مطابقة للموقع)

| الشاشة | من يفتحها | ماذا تعرض |
|---|---|---|
| **رحلتي ومناسكي** | الحاج | محطات الرحلة بترتيبها، نسبة التقدم، المرحلة الحالية، ووسيلة الانتقال لكل محطة |
| **برنامج المناسك** | من يملك صلاحية `manage_journey` (المشرف العام وموظف الحشود ومدير الحملة) | نفس المحطات مع إمكانية تغيير حالة كل محطة: لم تبدأ / جارية / مكتملة |
| **الخريطة والمواقع** | الجميع | مواقع الفندق والمخيمات والمشاعر من جدول `site_locations`، وفتح أي موقع في تطبيق الخرائط |
| متابعة مواقع الحجاج (داخل شاشة الخريطة) | من يملك صلاحية `view_locations` | آخر موقع شاركه كل حاج، وأقرب موقع للحملة والمسافة إليه |
| **بطاقتي وبياناتي** | الحاج | رقم النسك ونوع الهوية وتاريخ انتهاء صلاحيتها، والمخيم والمشرف المسؤول |

الحاج في التطبيق **يرى المواقع فقط** ولا تظهر له أي أداة إدارية، تماماً كما في الموقع.
ومشاركة الموقع الحيّة تتم من الموقع لأنها تحتاج إذن الموقع من المتصفح.

## الصلاحيات داخل التطبيق

الخادم يرسل مع تسجيل الدخول قائمة صلاحيات وظيفة المستخدم المقروءة من جدول
`job_permissions`، والتطبيق يبني شاشاته عليها:

</div>

<div dir="ltr">

```dart
if (ApiService.can('manage_journey')) { ... }   // بطاقة إدارة المناسك
if (ApiService.can('view_locations')) { ... }   // متابعة مواقع الحجاج
```

</div>

<div dir="rtl">

فبطاقة «برنامج المناسك» تظهر لموظف الحشود ولا تظهر للموظف الصحي، ومتابعة
المواقع تظهر للصحي ولا تظهر لموظف الإعاشة — نفس ما يحصل في الموقع بالضبط.
والتحقق الحقيقي في الخادم على أي حال، فحتى لو فُتحت الشاشة لا تُنفَّذ العملية.

## كيف يتصل التطبيق بقاعدة البيانات

التطبيق لا يتصل بـ MySQL مباشرة — يرسل طلباته إلى ملفات PHP في مجلد
`website/api/` وهي وحدها التي تفتح قاعدة البيانات، تماماً مثل الموقع.
بهذا تبقى بيانات الاتصال على الخادم ولا تصل للجوال إطلاقاً.

- تسجيل الدخول: `auth.php?action=login` — الخادم يتحقق من كلمة المرور
  بـ `password_verify` ويحدد الدور والقسم من قاعدة البيانات.
- ملف الحاج: `pilgrims.php?action=get`
- ملف المشرف ووظيفته وصلاحياته: `supervisors.php?action=profile`
- بيانات الحملة: `campaign.php?action=get`
- برنامج المناسك ومحطاته: `journey.php?action=program` و `journey.php?action=set_status`
- مواقع الحملة ومواقع الحجاج: `location.php?action=sites` و `location.php?action=pilgrims`

المسمى الوظيفي للمشرف صار يُقرأ من جدول `jobs` عبر `supervisors.job_id`،
بدل استنتاجه من آخر رقم في العضوية.

## الإعداد قبل التشغيل

افتحي `lib/services/api_service.dart` وعدّلي سطراً واحداً فقط:

</div>

<div dir="ltr">

```dart
static String baseUrl = 'http://10.0.2.2/website/api';
```

</div>

<div dir="rtl">

| الحالة | القيمة |
|---|---|
| محاكي أندرويد مع XAMPP على نفس الجهاز | `http://10.0.2.2/website/api` |
| جوال حقيقي على نفس الواي فاي | `http://192.168.1.5/website/api` (ضعي IP جهازك) |
| محاكي iOS على ماك | `http://localhost/website/api` |

ثم:

</div>

<div dir="ltr">

```
flutter pub get
flutter run
```

</div>

<div dir="rtl">

> **مهم:** الاستضافة المجانية InfinityFree تحجب أي طلب لا يأتي من متصفح
> (ترد بصفحة تحقق `aes.js` بدل البيانات)، فلا تصلح لتشغيل التطبيق.
> التطبيق يعمل مع XAMPP محلياً أو مع استضافة مدفوعة.
